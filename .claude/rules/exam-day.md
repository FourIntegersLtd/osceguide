# Exam day: what to know

Owner: `institution-owner`. Proof: `verify-institution` (clock and rooms also
`verify-attempt-engine`). Hire is exam mode: a GP lead is an org admin reviewing exam-mode
sessions, not a separate product. B2B defines its own exams and never waits on the platform
catalogue (ADR 0017); do not build against an open decision in `web/docs/BACKLOG.md` (D7-D10).

- **The circuit runs itself** (ADR 0018). The server owns the clock: read `remaining_seconds` and
  `phase_ends_at`; never run an authoritative countdown in the browser.
- The patient is dispatched on the server's clock when reading ends; if nobody joined the room
  during reading, the circuit sits overdue for ever. Starting the room is `attempt-engine-owner`'s.
- **`trainee_id` means two things.** Circuit slots use `users.id`; result decisions use `trainees.id`.
- A slot's attempt must be `kind = 'exam_slot'` (`kind_matches_reference`). To put marked work in
  front of an examiner locally, copy a marked attempt as an exam-slot attempt:
  `web/.claude/skills/verify/features/feedback-fixture.sql`.
- Deactivating a trainee cleans their slots; a sole admin cannot be locked out; a stale revision
  is refused (`stale_revision`); a cancelled or edited sitting notifies (`sitting_emails`).
- Dashboard read models: `service_org`, `service_live`, `service_readout`, `service_report*`,
  `service_trainee`. The learner's own home, performance and achievements files are
  `web-foundation-owner`'s; the staff console's are `staff-console-owner`'s.
- A review screen renders for a slot with no attempt; a local DB has exams and rubrics but often no
  stations or marked attempts (`features/rubric-builder.md` has a fixture needing neither).
- Reporting and exports are paged and server-filtered: assume more than one page.
- Web: `domains/assess` composes capabilities; permission gates use `can()`, never a role.
  Four skins share tokens (`docs/DESIGN.md`): no literal colours.
- A feature touching these files runs every arm's journey that renders them
  (`docs/CORE-JOURNEYS.md`, `npm run e2e:assess` against a local api on :8002).
- Institution and hire are not consumers: no Payments/Referrals tabs, plan or trial copy, upgrade modal,
  "personal practice" link, Community, A to Z, Slides, Podcast or Athena (`athenaOffered` in
  `surfaces/jumpTo.ts`). Shared train screens take `surface !== "train"` and use the "ask your administrator" wording.
- **The board and console are pushed, not polled by heartbeat.** `snapshot_on_heartbeat=True` is allowed only in `voice/service.py` and `health/service.py` (`test_no_heartbeat_snapshots`). Every write that changes what the console shows must announce: clock and sitting writes call `announcements.circuit_changed`; an attempt moving status on a slot calls `sittings_reads.attempt_progress(session, attempt)` (attempts cannot import `announcements`; it is re-exported by `service_reads`); ending a person's unstarted stations announces `candidate_absent`. A new write that changes a console fact without one leaves the screen stale. Time-derived alerts (`no_running_attempt` after 20 s, `clock_overdue`) refresh on a stream heartbeat **only while** `worker_running` is false, so a down worker does not freeze overdue warnings on an open tab.
- **Reports are batched.** `sitting_detail` reads slots with one `slots_for_circuits`; report and cohort group slots by candidate once. The results CSV is a generator (`stream_sitting_results_csv`) and the audit row is written before the first byte. Roster import is `INSERT ... ON CONFLICT DO NOTHING` per row inside `begin_nested()`; any `AppError` skips that row with its code. `released_outcomes` tests released-ness on the current revision only (an older released revision never counts).

- **Circuits and breaks.** An exam-mode circuit is one candidate; a training circuit needs one station per trainee and has no breaks (`domain_run`). The exam's break is `exams.settings.default_break_minutes` (1 to 60, no column); the Schedule wizard seeds from it (`examTimings`). Sitting and org rows carry `circuit_count`/`candidate_count` from one aggregate (`totals_for_sittings`): never count per sitting. `overdue_seconds` is derived from `phase_ends_at`/`paused_at`; `voice_fault` shadows `clock_overdue`, so a test cannot assert both. "N not joined" is `OrgCounts.invited_not_joined`.
- **In a worktree, `poetry run` and `make` use a fresh venv with no deps**: put the main venv's `bin` on PATH, set `PYTHONPATH=.`, and run `ruff`, `mypy app`, `pytest -n auto` directly.
- **Seeding a board spec.** Trainees list by `created_at, id`: one bulk call stamps every row alike and the id breaks the tie at random, so seed a named person per call in board order. Seed only reserved-domain addresses (`seed-people.ts`; real domains queue real emails). One `createOrg({prefix, role, adminName})` and `register()` in `e2e/support/api.ts` own the org, the 429 wait (30s x 8) and a 409 on an existing address; build paths with `orgPath(slug, tail)`, exams with `publishedExam` (`seed-exams.ts`), SQL literals with `q()` and ids with `userIdByEmail` (`db.ts`). Seeded addresses (`addr()`) repeat across runs and specs and `users.last_login_at` outlives the org: `addTrainees`/`addStaff` reset it to NULL and only `haveSignedIn` sets it, or "invited, not accepted" depends on spec order. Use `--output` of your own so parallel runs do not delete each other's `test-results`.
- **People board width.** The board's `.page` is 1080px, the assess page token is 1120; People sets `max-w-[1080px]`. `PeopleDialog` is `Modal` (focus trap, scroll lock, Back) at 32.5rem, not a hand-rolled overlay.
- **Settings board.** The frame (eyebrow, h1, tab strip) for org surfaces is `SettingsFrame` in `capabilities/account/Settings.tsx` (`surface !== "train"` branch); panels are `settings/SettingsCard`. Account and Preferences panels are the shared account capability (access-owner). Board card titles are 16px (`cardTitle`), not the shared `h2`. Board invoice numbers are four digits (`INV-2026-0142`) and the api's are `INV-<year>-<sequence:06d>`, so they cannot collide with `invoice_number_seq`; only a previous run's board number is renamed out of the way (`seed-settings.ts`). The Invoices tab of Settings is a link card with no invoice rows; `board-invoices.spec.ts` scores the rows. Specs write to your own `--output` and log file, never the shared `$TMPDIR` (parallel agents overwrite it); macOS has no `timeout`.

## What a failure looks like here
- A candidate is locked out of, or dropped from, a sitting partway through.
- The browser's clock decides a phase instead of the server's.
- One organisation sees or acts on another's sittings, roster or results.
- `users.id` and `trainees.id` mixed up, so the decision lands on the wrong person.
- A list or export reads one page and drops the rest.

- People dialogs (`domains/assess/ui.tsx`, shared by people, roster, team, settings, reporting): `PeopleDialog` hands `Modal` a stable `onClose` (ignored while busy) and `closeOnBack={!busy}`: a Back the dialog ignored still consumes its history entry, so after a failed save the next Back would leave the page. It also needs `labelledBy` and `hideCloseButton`, or the title is read twice and the X bar overrides the padding. One dialog from open to close: do not swap two `PeopleDialog`s as data loads.
- AddPeople board: its empty `.acts` slot wraps under the heading on a narrow screen, so the app keeps the same empty slot to match at 760.
- **Schedule wizard board spec.** The draft opens in training: click the Formal radio first. The wizard offers only org-owned published stations of the exam code (seed them via `/stations` then `publish`), and a training circuit needs trainees >= stations. The board re-renders on a click and drops any wrapper you added, so wrap `#cmp` after the last click. Select the Exam by `#sitting-exam` (`getByLabel("Exam")` also matches the "Exams" link). Check people through the row label, not the sr-only input (a force click can miss when the input is under the top bar).
- **Results boards.** The sitting progress rail's `.st` is content-box on the board (110px + padding + border), so `boardRailStep` basis is 136px; at 760 the board wraps 4 + 2, the app wrapped 5 + 1 until then. The release step's note counts as soon as anything is signed off ("0 of 8 released"), not only once released. A draft decision may have a null outcome and null rationale (the board's Ben): seed it so, or Sign off is enabled and the warning bar is absent. Slot review (`SlotReview.tsx`) is a different structure from its board (step chips, one column, G/A/R grids vs the board's two columns and segmented rows): 52% at 1440, a rebuild, not a tweak.
- **Exams board spec traps.** A draft exam cannot take a programme or a station template (the api refuses), so the board's Draft and Retired programme rows and a template under Y4-MOCK are unreachable. An exam with a scheme version cannot be deleted: New exam steps need a random short code per run. The board's `.dlg` is content-box 568px; `.wrap` is 792 wide (760 + 32 padding), so at a 760 viewport the app needs `w-[calc(100%+2rem)] max-w-[792px] self-center` to match. `Select` puts `className` on a wrapper span: size the control with `[&>select]:min-h-11`. Selected cards use `bg-assess-selected-bg`, never `bg-osce-accent-light` (saturated). A second `next dev` in `web/` needs `NEXT_DIST_DIR`.

- **People board spec traps.** `addStyleTag` takes plain CSS: Playwright selectors (`:text-is`, `:has-text`) there are silently ignored, so size an app card with `evaluate` instead. The board's first `Revoke` on Staff is the owner's disabled button (use `last: true`); card states sit in a two-column `.g2`, so give the app card the board card's measured width. `PeopleDialog` caps its panel at `max-w-[35.5rem]` or Modal goes full width below 768px. Trainee and staff lists carry `role="table"`/`"row"` (the ASSESS-5c journey reads rows); GroupMembersDialog clears its ticks on close.
- **A restyled screen keeps its accessible names.** The journeys find the sitting rail as `getByRole("list", { name: "Steps" })`; the board's `.rail` is bare divs, so the rewrite dropped it and only `build-sitting` (CI journeys) noticed. `SittingDetail` renders `<ol aria-label="Steps"><li>`, and `board-sitting.spec.ts` asserts six items and "Circuits" before any pixel diff. Run `build-sitting.spec.ts` with any board spec that touches a screen a journey walks. A transient 403 on an admin read in a journey right after an api edit by another agent (uvicorn reload) passed on rerun: rerun before chasing it.
- **Schedule wizard seed.** 7 roster people (Daniel, 4th, unjoined) and 6 published stations. Formal picks 6 people (supervisor-each picks 3: the board lists 3 + "and 4 more"), training 6 stations and 6 trainees. The people list is 2 rows longer than the board's 5 (its "Group: Firm B" row stands for 4 people), so people-* only pass with the scoring stand-in. The `.tabs` strip stretches full width (no `self-start`). Hide the board's training Breaks block with `div[style*="border-top:1px solid #EFEFF2"]` after the last click.
- **Console board seed titles.** Seeding board-like station titles (`ensureTitledStations` in `e2e/support/seed-sittings.ts`, `STATION_TITLES` in `seed-console.ts`) moved tabs 1-3 by under 1 point: wrapping was not the driver. Spacing and the training seed (the board's tab 2 shows the 6-person circuit; the seed has 3 trainees and 3 stations) are. `/api/v1/stations` takes `search=` (title fragment), not `q`, and `limit` over 50 is a 422.

- Board-match dialogs: `board-console-states.spec.ts` hides dialog text on both sides and caps the app's add-trainee list to 2 rows; the board draws a disabled "not yet joined" row the app does not. Exceptions are in `docs/institution-overhaul/verify/board-diff/console-exceptions.md`.
- **Trainee boards** (`domains/assess/trainee/traineeBoard.tsx`, seed `e2e/support/seed-trainee.ts`, specs `board-trainee*.spec.ts`, `board-self-practice.spec.ts`). `JoinRoom` auto-joins on load: hold `**/join-token` in the app page or the hero turns into "Connecting the patient"; the March mock needs `readingMinutes: 600` so it stays in reading. One cached org (`$TMPDIR/board-trainee-org.json`, same calendar day; delete it after a seed change). An exam slot's review reaches the candidate only after a completed `gp_lead_reviews` row (a completed `slot_reviews` row alone reads "Not marked yet"); SelfPractice needs published org-owned stations or it scores the empty state. A `hidden` capability needs `includeHidden: true` to link. `space-y-*` plus an sr-only child shifts the next block 11px: use `flex flex-col gap-3`. A board card with rows only: `TraineeList untitled`. Compare the board's `.page` with the labelled `section`, never `.main` while old chrome is in place. TraineeSitting is structural only (20 to 40%: rooms, clock and Join differ).
- **Hire and Partner boards** (`board-hire.spec.ts`, `board-partner.spec.ts`; seeds `e2e/support/seed-hire.ts`, `seed-partner.ts`). The hire dashboard shows the setup assistant until an org-owned station is published, so seed one. An exam circuit is one candidate (more is `invalid_circuit`), and a decision needs sitting status `completed`. The hero status strip is portalled out of the compared section (`statusHost`). The partner seed writes `partner_arrivals` and `acquisitions` by psql (no payments, so Paid is 0). `/growth/partners/{p}/ref-ids` is empty for a non-pilot partner, so the Reporting list is hidden on both sides in the diff. Fee bars are the real daily series (five bars vs the board's seven weekly): masked on the phone fee tab only. `getByText` on a dialog title matches the sr-only heading too: use `getByRole("dialog", { name })`.
- **Board controls have one copy.** Buttons, inputs, labels, avatars, cards and chip/alert tones live in `foundation/ui/boardKit.ts`; do not redefine them in a screen's chrome file. `boardInput` keeps the browser's 1.5 line height (no `!leading-[normal]`): it sets a textarea's height and the SittingResults decision-rhythm score (8.9%, 10% bar) moved to 13% without it. The authoring "Empty and read-only states" tab is the Exams board's sixth tab and is dev-only (`NODE_ENV !== "production"`). The partner fee note shows the server's `billing_disclaimer`, so its height differs from the board's fixed note (Partner overview/fee score ~9-16%, data-driven).

- **Picker standing is three states, not two.** `candidateStanding` (`scheduleSitting.ts`): no account is "Not joined yet", an account nobody has signed in to is "Invited, not accepted", the rest "Signed in". Both of the first two can be scheduled; never write copy saying an unaccepted person cannot be. Console and home copy must not assert a completed state ("Everyone is in", "Every review is complete") the data does not show: a circuit with no station sat says "No one sat this circuit".
- **Admin guard counts accepted admins only.** `active_admins_besides` skips deactivated admins and those with `invitation_pending`, so the only working admin cannot revoke themselves while the other has not signed in. A test admin from `make_actor` is invited unless `signed_in=True`.
- **Absent candidates.** The results index row has `sat`; screens use `undecided(row)` (`results/support.ts`), never `not_decided` alone. A bulk import stamps `created_at` in file order (the list breaks ties by random id otherwise).
- **Home boards** (`board-today`, `board-supervisor`, `board-live-board`; seed `e2e/support/seed-home.ts`; shared parts `domains/assess/dashboard/BoardParts.tsx`). Pin the board's date and greeting with `page.clock.setFixedTime` and rename the admin by psql ("Dr Okafor"), else the greeting reads "Good morning, Ms.". Seed run history by psql into `circuit_run_history` (the api has no seam). The board's `.row:first-of-type{border-top:0}` quirk is the `first` prop on `BoardRow`. On LiveBoard hide `details.fold,.note` and pick cards with `.card:not(.fold)` (`div:has(>details.fold)` hides `.page`). `w-30` is not a Tailwind 3 class: use `w-[120px]`. `ExamClock plain` gives a bare span for rows. Phone limits are 12% for Supervisor (seeded rows wrap) and Now running (clock wraps).
- **Circuit console layout** (`CircuitRunner`). A hero (`CircuitHero`) leads with the phase, the server clock (`ExamClock plain tick`, no browser countdown) and one primary action (Start circuit / Next station), Pause/Resume beside it; Extend, Reset, Resend and End are in the shared `ActionMenu` (End last, disabled items say why). Main column: station progress, the candidate's brief. Right rail (`Rail`/`RailSection`): the room, mark, record, feedback, interventions, folded by default and remembered in localStorage (`railState.ts`, try/catch). Never add a button row back to the hero. `run-circuit.spec.ts` opens "More circuit controls" to End.
- **The console's station content is the candidate's brief only.** `readCandidateSections` asks `/station-versions/{id}/sections?audience=candidate` (the server drops hidden blocks for it) and `candidateSections` filters again; the untemplated fallback shows `reading_brief`/`candidate_brief` only, never a dump of every field. Rendered with `AudienceSections variant="brief"` (the train doctor-information icons).
- **The ended console has one list and one next action.** `EndedActions` (in the hero) shows a three-step stepper, ONE primary from `nextReviewAction` (Mark next station, then Publish feedback, then Open results) and a "More circuit actions" menu. `StationProgressList` is the only stations list (Marking chip, Mark/Review per row); the TurnStrip, The room, "Mark a finished station" and "Stations to mark" are not drawn once ended. The rail keeps "The record", the feedback form and "What was changed by hand", closed by default; `openRailSection(id)` opens one from the hero. The marking page stays the only place a transcript opens (supervisor-only rule is the server's).

## Training circuit as a group room
- A practice circuit is a LiveKit room everyone joins; cameras off by default, patient tile first. Only the current trainee and the supervisor are heard: `mic_allowed` (sittings) decides, `set_mic_permissions` applies it, the supervisor drives the floor (`/floor`), per-person mic (`/participants/{identity}/mic`) and `/room/close`. The room stays open after End until "Close the room" (or the reaper closes it six hours after End). Mic changes go through `run_after_commit`, never LiveKit under the row lock and never for a rolled-back request. Exam circuits never use any of this; their tests must stay unchanged.
- Identities: trainee `str(user_id)`, supervisor `observer-<id>`, patient `agent-*`. The training token `display_name` carries the person's name (never an exam token) (`roster.names_for_users`); `tileName` ignores an id-like name, so an old token still reads "Trainee"/"Supervisor".
- Peer marks (`slot_peer_marks`, migration e3f4a5b6c7d8): trainees watching a turn mark it G/A/R with comments; keyed `domainId` or `domainId.competencyId`; publishes `circuit.peer_marks_changed` on the circuit topic so the console refetches (no polling). The consulted trainee reads them via `GET /me/slots/{slot}/peer-marks` only once the slot is published and never for their own turn. There is no "feedback published" notification yet.
- Live marking reuses `PUT /orgs/{org}/slots/{slot}/reviews/mine` (draft, `partial: true`: ratings merge, notes stay, a completed review answers `review_already_completed`). Saves go through `createSaveQueue` (one in flight, in order). Peer ratings are G/A/R; an empty mark deletes its row; Redo clears the slot's marks. An org admin's marking page opens the GP-lead form, so their live drafts are not pre-filled there (known gap; in an exam `LiveMarkPanel` says so to a viewer with `sign_off_results`).
- One card, one splitter (`room/SplitCard.tsx`): the page never scrolls; the scheme panel is an accordion with a sticky progress header.
- An ended circuit's console stream is shut (`useCircuitRun` latches `ended`), so an action after the end must redraw through `run.run(...)`: "Close the room" does (`CircuitRunner` passes `onClose`), else the supervisor's room rejoins a closed room until reload. In reading time the primary reads "Start <person>'s turn" (advance starts the current consultation); "Bring in <next>" only in consultation.
- **A live exam console is one `SplitCard`** (as training's): "Listen in" (`ObserverPanel`, subscribe-only) beside `LiveMarkPanel peers={false}` (no peer marks in an exam); the hero reads `examNowLine` ("Now: <candidate> · Station N of M") and keeps "Next station" as its primary. `LiveMarkingSidebar` is gone: a finished station is marked from Station progress. Exam join tokens last 15 min (`livekit_exam_token_ttl_seconds`), training 5: safe because `JoinRoom` refetches `/join-token` on any unexpected drop or connect error and LiveKit does not cut off a connected participant when its token expires. A join is still allowed after the candidate's own station completes while the circuit is live (not changed here). Locally, Turbopack rejects a symlinked `node_modules` (worktrees): run `next dev --webpack --port 3101` with `PLATFORM_API_URL` and `E2E_REUSE_SERVER=1`. `run-circuit.spec` ASSESS-3 expects voice_unavailable, so it fails when `api/.env` has LiveKit keys.
- **Hire is the same screens with other words**: `useAssessWords()` (`vocabulary.ts`: Assessment, Candidate, Rotation, Intake, Assessor / Lead assessor via `teamRoleLabel`) and `assessErrorMessage(cause, w)`; pass `w` to every new error caller, and `joinFailureCopy(cause, w)`. A route hire refuses is listed in `surfaces/hire/surface.ts` `HIRE_SCREEN_NAMES` and renders `NotOnThisAccount`. Staff reach an employer org from the switcher's "Hiring" group only with a membership (`switch-workspace` needs one; do not widen). Local test org: `node scripts/seed-demo-org.mjs --employer --email walkthrough@example.com --password "correct horse battery"` (the verify account; `dev@example.com` does not exist locally).
- **Hire Part 2 (web only, no api change)**: `dashboard/hireSteps.ts` + `HireSetup.tsx` (first-assessment checklist from `OrgSetup`, shown on HireHome's New account state), `rotations.ts` + `RotationBuilder.tsx` (deal N candidates across M assessors into rotations in the schedule wizard, then the normal `circuits/bulk` call), `results/ranking.ts` + `CandidateRanking.tsx` (ranked comparison on the decision screen; a "hired" outcome needs a reason note, enforced in the browser and by the api (`hire_reason_required`)). Wizard step labels, titles and help go through `scheduleWords(text, w)` (`scheduleSitting.ts`): Assessor / Rotation / Assessment in a hire workspace, unchanged otherwise. Not built, each needs api: per-station assessors, staggered start times, exam templates, CSV shortlist export, appeals, retention and delete-on-request.
- **macOS case-clash trap**: `hireSetup.ts` and `HireSetup.tsx` are the same file on a case-insensitive disk. Name a module's logic file for what it does (`hireSteps.ts`), never the component's name in another case.
- **No-show and dropped connection (`sittings/service_attendance.py`)**: `POST .../mark-absent` (body `trainee_id` = the person's user id, `reason` required) skips their unsat slots, records a `mark_absent` intervention (`clock_moved=False`) and the audit row `circuit.candidate_marked_absent`, and ends the circuit when nobody is left to sit; `candidate_already_sat` (409) once they have an attempt or a started slot. `POST .../allow-rejoin` (reason required) re-sends the patient on the *same* deadline, once per slot (`rejoin_already_used`), only when the live attempt has ended (`candidate_still_connected` otherwise); more time is still Add time. `join-token` refuses a marked-absent person with `candidate_marked_absent`. `MySitting` carries `marked_absent` and `waiting_for_rejoin` for the candidate's plain message. `redo_station` is unchanged and still gives a fresh reading period, so it is not the re-join. Trap in tests: the app session caches attempts, so set a status with `attempts_repo.set_status` then `_test_session().expire_all()`, and do any 4xx check before an uncommitted update (a refused request rolls the savepoint back).
