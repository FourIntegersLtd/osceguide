# Handover — platform-api

You are picking up a greenfield backend that replaces two legacy ones. This
tells you where it is, what is true, what is not, and the three habits that
matter most here. Read it before `STATUS.md`.

## What this is

`platform-api` unifies `backend/b2c-api` (Flask + Firestore, consumer) and
`backend/b2b-api` (FastAPI + Supabase, institutions) into one backend, serving
consumers, institutions, partners and the LiveKit workers from the same core.
Both legacy backends are still live and untouched.

- **Where:** `backend/platform-api/`, in the `backend` git repository, on branch
  `feat/tutor-memory` — pushed, and checked out in the worktree
  `backend-tutor-memory/`. Despite the name that branch is the whole revamp:
  `feat/platform-api`, `feat/authored-exams-and-rubrics` and
  `feat/assessment-cutover` are merged into it, and it is what goes to `main`
  next. `main` itself is a superseded snapshot — roughly half the routes, no
  rubrics, no tutor, no circuit automation. Read the branch, not `main`.
- **Stack:** FastAPI, Pydantic v2, SQLAlchemy 2.0 async on psycopg 3, Alembic,
  Postgres, procrastinate for jobs, Redis for ephemeral state only.
- **Spec:** `~/.claude/plans/we-are-going-to-happy-frost.md` — the remediation
  plan first, the original architecture proposal as its appendix. The proposal
  is still the specification; the invariant catalogue (A1–A8, C1–C10, S1–S2,
  T1–T5, P1–P5, E1–E4, R1–R4, W1–W2) is referenced by ID throughout the code.
- **Method:** `CONTRIBUTING.md` — an eight-step test-first cycle. Follow it.

Two sibling repos matter. `assessment-platform/` holds the LiveKit workers and
the `osce_assessment` engine, which owns every prompt template and the
evaluator. `frontend/` is the Next.js app; branch `feat/platform-api-client`
has a typed client that nothing imports yet.

## Start here

```bash
cd backend/platform-api
make db-up && make migrate        # Postgres on 5433, Redis on 6380
make engine-dev                   # installs osce_assessment from the sibling checkout
make ci                           # lint, mypy, import-linter, guards, tests, status-check
make start                        # http://localhost:8002/docs
```

`make ci` must be green before you commit. It takes about 90 seconds and needs
Docker.

## The most important thing to understand

This project was audited on 2026-09-16 and **the core did not work**.
`attempts.definition` was written in exactly one place and the only caller was
a test fixture, so every real attempt had `definition = NULL`, the worker
bootstrap refused it, and no candidate could ever run a station. 2,369 tests
were green.

The cause was a single process gap: **domain rules were written with unit
tests, then services were written, and nothing checked that a service called
the rule.** Twenty of 101 rules were tested, documented in a slice README,
advertised in the OpenAPI error list, and never executed.

So:

1. `tests/guards/test_domain_rules_are_reachable.py` now fails when a domain
   rule has no production caller. `KNOWN_UNWIRED` is a **debt list, not an
   exemption list** — a second test fails if an entry becomes reachable and is
   left there. Two remain, both deliberate. Shrinking it is real work, not
   bookkeeping.
2. `docs/STATUS.md` is half prose, half generated by
   `scripts/status_report.py`. `make status-check` runs in CI. Do not hand-edit
   below the marker; run `make status`.
3. A green suite is not evidence a feature works. Ask what would fail if the
   feature were deleted.

## Three habits this codebase expects

**Plant the violation.** Every guard has a meta-test that proves it can fail,
and the meta-test must use the shape the codebase actually has.
`test_org_scoped_repositories` passed for months while inspecting *zero*
functions: it walked `ast.ClassDef` and matched `org_id` inside SQL strings,
and after ADR 0013 restored SQLAlchemy the repositories were module-level
functions using ORM predicates. Its meta-test built a class holding raw SQL — a
shape that exists nowhere here — so it looked alive. When you fix a bug, break
it again and watch the test fail.

**Ports and fakes, never `patch("module.attr")`.** `app/core/ports.py` holds
the Protocols; `tests/support/fakes.py` holds the fakes. A fake should record
enough to check the *order* of operations — that is how a double agent-sweep
was caught in code I had just written.

**Say what is not true.** If a test has never run, write that down. If a lock
is not proven by the test next to it, say which test does prove it. There is an
e2e test in this repo that has never executed; it says so in its own docstring.

## Layout

```
app/
  main.py               composition root; the only place routers are mounted
  core/                 shared kernel — never imports a feature
  features/<slice>/     router, schemas, service, repository, models, domain, errors, README
  migration/            legacy importer; a leaf, deleted at decommission
scripts/                openapi export, status report, legacy import CLI
tests/ guards/ unit/ repository/ http/ contract/ e2e/ migration/ support/
```

Slices depend downward only, enforced by `import-linter` (`make arch`). The
layer order is in `pyproject.toml`. A slice calls another **service to
service**, never into its repository or models. Where the order forbids it —
`reviews` sits above `sittings`, but the edit lock needs review data — the seam
is bound once in `main.py`, the way `bind_role_policy` already is.

## What works, end to end

A candidate can be created, entitled (or given the free trial), start an
attempt against a published station, have the worker bootstrap it with a real
rendered prompt, stream turns, deliver a transcript, and read a scored result.
`tests/contract/test_attempt_is_runnable.py` is that path; start there.

A supervisor can create a sitting, build a circuit, start it, dispatch an agent,
switch turns, end a consultation, append latecomers and end the circuit.

## Things that will bite you

- `poetry run pytest -q | tail -2` shows the last two lines, **not** the exit
  code. A red suite looks green. Use `make test`.
- Scripted edits silently match nothing when `ruff format` has reflowed the
  line since you read it. Assert your anchor before writing.
- `git checkout <file>` is not an undo for uncommitted work. I destroyed a
  finished change that way; commit before planting violations.
- Postgres is on **5433** and Redis on **6380**, not the defaults. Set
  `DATABASE_URL` for anything outside `make`.
- `app/migration/` is exempt from three slice guards by design, and a guard
  stops anything importing it so deleting it stays a delete.
- Never push `assessment-platform` — push to main is the deploy (GHCR + K3s).
  Never push to the deprecated `livekit/` repo at all.

## Commit style

Explain *why*, and say what you got wrong. Recent commits are the model: they
name the defect, the evidence, the alternative rejected, and the mistakes made
on the way. The history is the design record for whoever comes next.
